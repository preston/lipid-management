Architecture

This application is clinical decision support for lipid management and cardiovascular risk scoring against FHIR R4 patient records. The shipped UI centers on the OpenCVDRisk calculator (AHA PREVENT™-aligned risk). CQL libraries also include BMI helpers and a LipidManagement pathway mapped to U.S. Department of Veterans Affairs / Department of Defense lipid guidelines.

Decision support only

Outputs from this application and its CQL libraries are decision support signals. They are not autonomous clinical orders and are not a substitute for clinical judgment.

How the application works

The browser talks to a FHIR server that holds patient data (or accepts a client-supplied Bundle), terminology (ValueSets), and decision-support logic (CQL Libraries). The OpenCVDRisk calculator calls Library/$evaluate to preload chart values into the form, then again when the clinician presses Calculate. Prefill reads the selected patient’s chart or custom Bundle. Calculate sends the current form values (and clinician exclusion flags) as nested CQL library Parameters; OpenCVDRisk coalesces those overrides over chart-derived inputs when computing risk. Optional ZIP → SDI decile is resolved by evaluating the SDI2019 library (chart Patient.address.postalCode by default, or a user ZIP override as OverrideZipCode), then passed to OpenCVDRisk as OverrideSdiDecile. OpenCVDRisk does not include SDI-2019, so chart-only LipidManagement stays on the base model unless that Parameter is supplied.

Risk scoring interaction

Prefill uses OpenCVDRisk and BMI $evaluate. Calculate re-runs OpenCVDRisk risk expressions with the current form values as library parameters (plus chart or custom Bundle data for anything not overridden).

Standalone mode

Point the app at a FHIR server in Settings. With developer mode enabled, the Loader can upload Libraries, ValueSets, and optional example data. On the calculator, search for a patient on that server, or open a custom FHIR Bundle JSON file (for example Synthea). Custom files are sent to $evaluate as the data parameter with useServerData set to false, so the server does not mix in its own patient data.

SMART-on-FHIR mode

The EHR launches /launch with iss and launch. After SMART authorization and patient context, the calculator uses the same CQL preload and Calculate $evaluate path against the EHR FHIR server. Custom client Bundles are not used in SMART mode.

How clinical logic is packaged

CQL source and ValueSet terminology ship with the app under public/. The Loader (Settings → developer mode) uploads them to the configured FHIR server before evaluation.

  • CQL under public/cql/ (BMI, SDI-2019 / Library id SDI2019, OpenCVDRisk, LipidManagement) is uploaded as FHIR Library resources via PUT to each Library id (contentType: text/cql, base64-encoded body). Loader order: BMI → SDI-2019 → OpenCVDRisk → LipidManagement.
  • Terminology under public/value-sets/ is FHIR ValueSet content inside transaction Bundles; the Loader POSTs those Bundles to the server base URL.
  • CQL valueset URLs must match the ValueSet.url values stored on the server.
  • The browser does not interpret CQL for risk or pathway scoring; the FHIR server evaluates uploaded Libraries against patient chart data or a client-supplied Bundle, including any nested library Parameters sent by the calculator on Calculate.

OpenCVDRisk and PREVENT™

The OpenCVDRisk calculator and library are an open-source implementation of the American Heart Association (AHA) PREVENT™ algorithms for adults ages 30–79 without known cardiovascular disease. They do not use AHA source code or AHA assets requiring a license from the AHA. This is not an official AHA product and is neither affiliated with nor endorsed by the AHA. Coefficients follow Khan Supplemental Table S12A–J (base and optional UACR / HbA1c / SDI models for 10- and 30-year Total CVD, ASCVD, HF, CHD, and Stroke). Optional predictors use preventr-style model selection. SDI deciles come from the Robert Graham Center 2019 ZCTA Social Deprivation Index (SDI_score centile → decile 1–10), baked into SDI-2019.cql (SDI2019). The calculator resolves ZIP→decile with SDI2019/$evaluate and passes the result as OverrideSdiDecile. LipidManagement chart-only evaluate stays on the base model unless a host passes optional Parameters (including OverrideSdiDecile).

Statistical model: Khan SS et al., Circulation. 2024;149:430-449. DOI: 10.1161/CIRCULATIONAHA.123.067626.

Guideline basis

The LipidManagement CQL library maps the VA/DoD Clinical Practice Guideline on Lipid Management for Cardiovascular Disease Risk Reduction (2025), including the adult management algorithm (Appendix G / figure page 20). That library is loadable with the other CQL packages; the current UI evaluates OpenCVDRisk (and BMI for prefill), not LipidManagement pathway expressions.
